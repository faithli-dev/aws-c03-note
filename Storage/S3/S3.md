# Amazon S3

Amazon S3 is a regional, highly durable object store. Data is stored as objects inside globally unique buckets.

## Buckets and Objects

- A bucket belongs to one Region and has a globally unique name.
- An object consists of a key, value, metadata, tags, and a version ID when versioning is enabled.
- The key is the complete path-like string, such as `photos/2026/profile.jpg`; folders are prefixes, not real directories.
- S3 is designed for large objects and can scale to very high request rates. It is not a POSIX file system.

## Security and Access

- IAM policies control a principal’s S3 API permissions.
- Bucket policies are resource-based JSON policies and are useful for public access, cross-account access, or service access.
- Block Public Access protects against accidental public exposure. Keep it enabled unless a deliberate public design requires otherwise.
- Use IAM roles for EC2, Lambda, and other AWS services instead of storing access keys in code.

## Core Features

- Versioning preserves object versions and supports recovery from accidental overwrites or deletes.
- Replication requires versioning on both buckets. CRR copies between Regions; SRR copies within one Region. Existing objects need Batch Replication.
- Storage classes range from S3 Standard for frequent access to IA, Intelligent-Tiering, and Glacier classes for colder data. Lifecycle rules automate transitions and expiration.
- S3 event notifications can invoke Lambda, publish to SNS, send to SQS, or route through EventBridge.
